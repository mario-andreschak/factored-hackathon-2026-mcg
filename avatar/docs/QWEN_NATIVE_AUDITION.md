# Spanish and Portuguese native Qwen audition

**Decision, 2026-10-01: rejected by the user after listening.** The delivered Chelsie Spanish and Portuguese samples were judged unnatural, with a Mandarin-influenced accent/Spanish-English mixing. This rejects these exact samples and preset; it does not establish the quality of every Qwen speaker or hosted variant. Further Qwen streaming/browser qualification is deferred. Audio, hashes, measurements and failure evidence are preserved; no production adapter is enabled.

`experiments/qwen_native_audition.py` is a two-sample quality experiment, separate from the application voice adapters. It loads the complete Qwen3-Omni Instruct Thinker, Talker and waveform decoder once and generates two native speech answers from fixed synthetic text: one requesting natural Colombian Spanish, one natural Brazilian Portuguese. It uses Chelsie, one of the model's three built-in speakers. Regional accent accuracy is an audition question, not a published guarantee. No banking data, room microphone, dedicated TTS model, provider key, public endpoint or persistent GPU is involved.

The [official Qwen repository](https://github.com/QwenLM/Qwen3-Omni) explicitly lists Spanish and Portuguese among speech input and output languages, permits custom system prompts, and writes native audio at 24 kHz. The Apache-2.0 repository and [ungated Instruct model](https://huggingface.co/Qwen/Qwen3-Omni-30B-A3B-Instruct) are pinned to source `e4235853125589c789f06a2dd83e9f4126df5e9d` and model `26291f793822fb6be9555850f06dfe95f2d7e695`. The manifest pins sizes and SHA256 checksums of 23 required assets, including all 15 BF16 weight shards; the total download is 70,530,503,760 bytes. No Hugging Face secret or acceptance action is required by this ungated snapshot.

## Commands and limits

From the repository root, `python avatar/experiments/qwen_native_audition.py --plan` is inert: no SDK, credentials, network, model download or output writes. Nine focused local checks run with `python -m unittest discover -s avatar/experiments -p test_qwen_native_audition.py -v`.

`--prepare-cache` creates one ephemeral CPU-only app and one model-only Modal Volume, `elsewhere-qwen3-omni-native-26291f79`. The download/checksum Function has an 1800-second timeout, at most four physical cores and 16 GiB host memory, one container and no Function retries. Normal bounded Hugging Face transport retries may occur within that deadline. Successful checksum verification commits the Volume and creates the ignored local `.local/qwen-native/cache.json` receipt. Partial or changed assets cannot authorize the GPU step.

The original `--execute` mode is now disabled and its spent admission marker/failure are preserved. Its artifact-transport failure is recorded below. The prepared correction first requires one explicit `--delivery-preflight`: a CPU-only Function with the same outbound network block writes an exact fixed public fixture to a separate output Volume, explicitly commits it, returns a tiny allowlisted size/hash receipt, and downloads/verifies it locally. It loads no model, reads no model cache and downloads no weights. Function/client limits are 30/60 seconds; an exclusive marker prevents automatic repetition.

Only after both exact cache and verified delivery-preflight receipts exist, the separately explicit `--execute-delivery-fix` can admit one corrected H100 80 GB GPU Function. Its timeout is 600 seconds, its inference subprocess timeout 540 seconds and client budget 675 seconds. It loads all weights on CUDA0 in BF16 with SDPA, caps each native generation at 128 Thinker and 384 Talker tokens, and makes exactly two generations. Container host resources are bounded to four physical cores and 96 GiB. Outbound networking is blocked, the Transformers/Hugging Face offline flags are set, implicit authentication is disabled, and runtime HF credentials are rejected. The script cancels its single Function call on completion or failure. The distinct `gpu-delivery-fix-admitted.json` marker preserves the original admission and permits exactly one explicit corrected attempt; there is no automatic retry. No alternative GPU, offload, quantization, dedicated TTS or model fallback occurs.

The correction mounts `elsewhere-qwen-public-native-audition-output` separately from model weights. Shared code validates/writes `es.wav`, `pt.wav` and `report.json`, closes the files, calls `Volume.commit()`, and returns less than 4 KiB of metadata rather than WAV bytes. Installed Modal SDK 1.5.5 performs that commit via internal `VolumeCommit`/`VolumeReload` RPCs; it does not use HTTP blob upload. The [official Volume documentation](https://modal.com/docs/guide/volumes) supports explicit commit before exit and outside-app file access. Actual commit behavior under the network block was tested in the CPU preflight below. Only the local client performs `Volume.read_file`; its async generator is wrapped in a true outer deadline of at most 45 seconds and the original remaining client budget. Exact relative paths, cumulative sizes and SHA256 hashes are checked before accepting artifacts. Signed storage URLs stay inside the SDK and are never printed.

Dependencies are pinned: PyTorch/torchaudio 2.8.0 and torchvision 0.23.0 from the official CUDA 12.8 wheel index; Transformers 5.2.0, Accelerate 1.12.0, huggingface_hub 1.4.1, NumPy 2.2.6, librosa 0.11.0, soundfile 0.13.1 and Pillow 11.3.0. The [pinned Transformers implementation](https://github.com/huggingface/transformers/blob/v5.2.0/src/transformers/models/qwen3_omni_moe/modeling_qwen3_omni_moe.py) supports SDPA and the native `return_audio`/speaker parameters. It completes Thinker generation before Talker and waveform decoding in this API. This audition therefore measures complete-answer generation time; it does not measure streaming first-packet latency or qualify full-duplex interruption.

## GPU fit and cost

The index declares 70,519,637,090 bytes of BF16 tensors, approximately 65.68 GiB. Three billion active MoE parameters do not reduce the stored full-model requirement. A single H100 is a short-text fit candidate, with an explicit free-memory guard and no fallback. The official Qwen memory table uses FlashAttention2 and longer video inputs; it does not prove this SDPA/text profile fits. A measured successful load and the recorded peak CUDA allocation are required evidence.

At [Modal's current Function rates](https://modal.com/pricing), 600 seconds at the maximum configured H100, four-core and 96-GiB allocation is about $0.82; the 1800-second CPU cache limit at four cores and 16 GiB is about $0.16. Image build/startup time and applicable transfer/storage charges are additional. Volumes currently include up to 1 TiB free; existing workspace usage determines whether this roughly 65.7-GiB cache exceeds that allowance. This is a bounded experiment with scale-to-zero cleanup, not an ongoing service.

## Evidence to review

Successful artifacts are saved under ignored `.local/qwen-native/<timestamp>/`: `es.wav`, `pt.wav`, and `report.json`. Each file is bounded and WAV headers must declare mono signed PCM16 at 24 kHz. The receipt includes hashes, native Thinker captions, model-load and complete-generation timing, real-time factors, and peak GPU memory. Captions are model output, not independent transcription. Human language, accent and naturalness review remain separate from technical generation success. No production adapter or browser protocol is enabled by this experiment.

The corrected inert plan, syntax, both local SDK app definitions and nine focused checks passed. The approved CPU-only preparation completed successfully on 2026-10-01: all 23 files, 70,530,503,760 bytes, matched their pinned checksums and were committed to the named Volume. Local `cache.json` validates the exact revision and manifest SHA256 `2caf3d2b614a3dc5135f6b0ee8d3f221f153e34048007a216c5a03eed71cacfa`. No GPU was requested by this cache run; its app is stopped with zero tasks.

The parent then ran one approved H100 audition. It exited without locally delivered audio. The stopped app's logs locate the failure in Modal's result transport: `container_io_manager.push_outputs` called `format_blob_data`/`blob_upload`, whose R2 upload failed with `ClientConnectorDNSError` and temporary DNS failure. The GPU Function's `block_network=True` setting also prevented this large artifact upload. This is evidence of an artifact-delivery failure after Function return, not a logged model OOM or dependency failure. No waveform was recovered, so pronunciation, accent, naturalness and measured generation performance remain unaccepted. The exact app was stopped with zero tasks after 2 minutes 55 seconds. No automatic retry occurred; a reviewed artifact-preservation change is required before another bounded run.

Installed SDK 1.5.5 has separate default serialization limits: 2 MiB for synchronous invocation and **8 KiB for asynchronous invocation**. `Function.spawn()` uses asynchronous invocation; its output path applies the smaller limit. The original payload can therefore trigger HTTP blob upload while remaining well below 2 MiB. Server metadata can override these limits, and the original configured threshold was not captured. The corrected receipt is below 4 KiB and the actual preflight establishes its delivery.

The parent subsequently ran the explicit CPU delivery preflight. It passed: the 12,800-byte public fixture was written, explicitly committed, returned as a tiny metadata receipt, then downloaded and hash-verified by the local client under the same `block_network=True` worker restriction. No model cache, weights, inference or GPU were used. Its exact app is stopped with zero tasks (08:46:07–08:46:44 UTC−05 on 2026-10-01).

The parent then executed exactly one explicit corrected GPU audition.
