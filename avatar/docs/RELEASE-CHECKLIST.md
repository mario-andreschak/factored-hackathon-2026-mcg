Reviewed locally on 1 October 2026. The release target is natural spoken Spanish
for LATAM and Brazilian Portuguese, alongside the cinematic world and visible
Savia work. PersonaPlex's English quality was rejected by the user; prior native
English receipts below are historical transport evidence and cannot qualify this
release. Spanish conversation/talk-over is now human-accepted. Portuguese
subjective quality, quantitative microphone/AEC, actual three-style acceptance
and joined spoken backend-result narration remain required before release. See
the [canonical current native ledger](OPENROUTER_NATIVE_VALIDATION.md).

The ES/PT interface, character/scene copy, persisted language choice and
server-owned voice language policy are implemented. The earlier local check
passed TypeScript/Vite and 189 units with one optional upstream skip, including
17 isolated playback-ledger checks. The earlier
82-case browser suite passed 80 cases, skipped one optional real-Savia smoke,
and exceeded the 30-second aggregate budget in the ten-scene gallery case.
That gallery passed alone in 7.5 seconds after giving its ten deliberate
transitions a specific 60-second budget. Thus all 81 applicable pre-integration browser
cases passed across the full run and focused rerun. A subsequent native
language-switch regression also passed alongside all eight Gemini fixtures:
old capture/playback closes, late audio/captions stay fenced, and reconnect
requests Portuguese. This brought pre-integration browser coverage to 82
passes across those runs, with the optional real-Savia smoke still skipped;
no clean single-run aggregate or successful multilingual live conversation is claimed.
The earlier initial-selection source baseline passed 153 units and 77 browser
cases with one optional skip each. Its isolated Docker image was
`fd5b9905e7d7b7fbf1b1c3b3b32aaf5565a913293703ba9b397bb8121cf7d05b`.
That image predates the language changes and is not the multilingual release
image. The current native image has its own passed qualification; its evidence is
recorded separately below.

The complete goal remains active. See [open-weight options](OPEN_WEIGHT_VOICE_OPTIONS.md)
and [LATAM native audio evidence](LATAM_NATIVE_AUDIO.md) for the replacement decision.

their respective completion checks. The user accepted the retained preview from

launch/fixture failures remain historical and are superseded by that clean

The voice lifecycle tests cover response/audio-buffer cancellation; a delegated
read finishing during user speech or queued audible playback; retaining its real
output while deferring the next model response; duplicate tool-call suppression;
cancellation IDs; dropping late output after disconnect; fresh tool-call and
caption IDs after reconnect; and closing microphone tracks, capture nodes,
WebSockets/data channels, peers and audio contexts. Native result deferral does
not wait for a provider `turnComplete` event that may depend on the result itself.
Interim transcript hypotheses replace each other, and disconnect emits no stale
final caption. These tests do not establish provider latency, model quality,
acoustic barge-in, or successful natural remote conversation.

Test fixtures live under `e2e/fixtures` and are absent from the production entry.
Default browser tests avoid paid dispatch: a spawned test server has empty provider
keys and voice disabled; fixtures replace provider/worker transport with
deterministic routes. A
synthetic harness fetching the real loopback API grants Chromium's local-network
permission for that one test origin. Windows
uses installed Edge by default; override `PLAYWRIGHT_BROWSER_CHANNEL` if needed.
CI using bundled Chromium must first run `npx playwright install --with-deps chromium`.

## Authentication and privacy review

The server's fixed-target Savia proxy admits only the installed login/read/chat
routes and audited frontend assets. It rejects arbitrary worker URLs, action/admin
routes, traversal and client-selected customer/conversation IDs. The bank cookie
stays HttpOnly and is scoped to `/savia`; a separate HttpOnly avatar session maps
the server-held bank token. Savia independently checks ownership on each inquiry.
The parent uses permitted public chat output and actual controls; its bridge must
not read password/access-code values or send them to any voice model.

Public voice may begin before bank login by design. Remote deployment must use
explicit public bind, an exact HTTPS origin, Secure cookies and a trusted operator
access gate. Keep the origin listener private behind TLS ingress; authenticate
visitors there, strip client-supplied gate headers and inject the server-held gate
token. This protects provider spend independently of Savia account authentication.
Do not publish the origin listener directly or ship provider/gate keys to browser
code. Origin checks complement the operator gate and bank session.

Release checks must retain tests for foreign origins, DNS rebinding, missing avatar
session, bounded request/response sizes, provider error sanitization, timeouts,
rate/concurrency limits, cookie isolation, logout failure, fixed upstream route
allowlisting and public-gate rejection. Server tests own this evidence. Application
logs must exclude request contents, upstream failure bodies, cookies and keys.

The production entry serves only `dist`; `.env`, `.reference`, repository sources
and test harnesses must remain outside that directory. A source-level browser
fixture passing under Vite does not prove the production serving boundary; keep its
unit test and deployment smoke.
