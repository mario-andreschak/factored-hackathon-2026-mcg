## First five findings in discovery order

1. **Strength — generic/domain separation.** AGENTS.md establishes the boundary before the product entry point: domain work belongs here, Banking MCP or the isolated hackathon branch, while generic FLUJO main retains chat/flow/tool/MCP/execution interfaces. The copied generic implementation supports that division. References: `AGENTS.md`, `docs/FLUJO_PRODUCT_BOUNDARY.md`, `docs/submission/FLUJO_PLATFORM_EVIDENCE.md`.
2. **Strength — a persistent customer inquiry with real bounded reviewers.** README presents an unfamiliar charge that keeps its context and explicitly credits two completed model reviewers, helpful informational closure and retained suggestions. `team-story-summary.json` identifies two actual structured model workers; `savia_assistant/service.py` implements durable owner-scoped inquiries and two disjoint reviewer contracts. Their outputs choose approved suggestions; this is meaningful constrained review, not unrestricted autonomous investigation.
3. **Strength — the complete engine is the foundation.** README identifies all nineteen ordered R0–R18 rules and dates its older qualification. The source supplies actual authentication, attack/foreign-owner guards, consent readback, cancellation, owned selection, conversation routing, retry/clarification, ambiguity, eligibility, duplicate/risk handling and complaint status. `dispute_workflow/policy.py` performs no bank I/O; runtime and trusted host carry the authority. The current selected core/host replay passed 811 tests.
4. **Qualification — voice and card protection have separate evidence.** README’s native speech and card receipt claims are fictional-ledger capabilities, qualified independently. The shipped host resolves owned card selections; preparation does not write and confirmation rechecks admission. Current card tests exercise tampering, one receipt from 100 confirmations, logout and fresh-login recovery. The live canonical audit proves guidance speech and saved-status rereads, not narration of a newly confirmed block. References: `CARD_BLOCK_VERIFICATION.md`, `card-block-live/api-receipt.json`, `native-canonical-live/receipt.json`.
5. **Qualification — measured scale is not the full customer fleet.** README separates the two-reviewer recording, 100-team-conversation design, 300 client submissions and 18 live sandboxes. `INFRASTRUCTURE_CAPACITY.md` preserves the 217/300 initial reference result, 300/300 neutral repeat, provisioning failures and a later disabled-workspace root failure before delegation. These support capacity and collaboration within their workloads; they do not complete the ten-by-ten Savia customer investigation.

## Actionable gaps and declared limits

- **Human-grounded evaluation:** independently adjudicate the 120 labels and preserve disagreements; use a new untouched customer-like cohort for future routing/prompt changes. Measure safety misses and unnecessary escalation together. The automated eight-case audit is useful agreement evidence, not 120-case human truth.
- **Customer language and audio evidence:** the original n=3 customer comparison retains one Portuguese selected-fact failure. The later n=1 recovery is an 18.808-second trusted-host fallback, not a broad free-form quality result. Add human-judged ES/PT end-to-end cases, waveform comprehension checks and a frozen consent-to-block-to-spoken-outcome capture before stronger quality claims.
- **Durable observability:** persist bounded model usage/cost and explicit query/event linkage; define retention. Derive lifetime card-block outcomes separately from the current host action slot. Current snapshot reporting accurately discloses these omissions.
- **Fleet qualification:** the root failure on a disabled provider workspace produced no accepted native fleet result. Keep it separate from successful historical infrastructure evidence, and qualify any stronger customer fleet claim with conversation IDs, original-run recovery and reviewed outputs. This target does not block the working two-reviewer fictional submission.
- **Data operating guarantees:** source inventory assumes static objects rather than S3 VersionId pinning. Atomic pointer replacement protects readers from failed candidates but does not prove crash/power-loss durability or a transaction across filesystems. Partial external reports on failure remain possible while previous serving data stays intact.

No real refund, live banker acceptance, push/email delivery, multi-day endurance or measured repeat-contact/ROI outcome is demonstrated. The submission explicitly places these outside its demonstrated scope, so they are not treated as missing completion of the fictional-bank hackathon deliverable. The selected checks found no current critical consent, ownership, receipt or publication defect; their bounded coverage cannot prove the absence of every defect.
