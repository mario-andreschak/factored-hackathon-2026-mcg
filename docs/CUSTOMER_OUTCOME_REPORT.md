# Offline customer outcome report

Run `python3 -B scripts/report_customer_outcomes.py LOCKED_INPUT.json > report.json`.
This stdlib-only tool validates and summarizes **user-supplied offline evidence**. Its output does not verify the input's human review, trace provenance, installed graph, model/tool execution, deployed runtime or customer outcomes. Keep the locked input and raw traces in private immutable evidence. Do not put customer records, credentials or raw identifiers in the input or a public report.

Input is one JSON object with `schema: "customer-outcomes/v1"` and:

- `provenance`: nonempty `source_sha`, `fixture_id`, `fixture_version`, `trace_reference`, `data_origin: "team_generated_synthetic"`, and `evidence_tier` from `source_mock`, `simulated_runtime`, `native_trace`, `deployed_trace`. The tier is a supplied claim, not independently certified. This v1 records one source SHA and fixture for the full comparison; use separate locked inputs when system versions or fixtures differ, and do not compare those reports as a same-run result.
- `lock`: nonempty `workload_id`, lowercase 64-digit `case_set_sha256`, `locked_at_utc`, `rubric_version`, `status: "human_reviewed_locked"`, and at least two distinct `reviewers` (aliases). The tool checks presence and shape, not the actual case-set hash or reviewer identities.
- `cases`: unique `case_id`, `language` (`es` or `pt`), and `labels` containing `review_status: "human_reviewed_locked"`, nonempty `expected_route`, boolean `requires_handoff` and `in_scope: true`. Both languages are required. Labels and route correctness must be adjudicated outside this tool.
- `attempts`: exactly one baseline and one proposed row for every case and repeat, with unique `case_id/system/repeat` (positive integer). Each row needs `actual_outcome` (`safe_inquiry`, `verified_simulated_intake`, `correct_handoff`, `unresolved`, `unsafe`, `timeout`, or `tool_error`), boolean `automation_attempted`, `authorized_dispatch`, `safe_inquiry_resolution`, `intake_completed`, `transferred`, `handoff_packet_complete`, `unsafe_outcome`, finite nonnegative end-to-end `latency_ms`, and `cost_usd` plus `cost_basis`. Unknown cost is JSON `null` with `cost_basis: "unknown"`; a known zero requires `cost_basis: "documented_zero"`; other known values use `"measured"`. Include failures and timeouts as rows with elapsed latency. A completed intake claim also requires `authorized_dispatch: true`, `confirmation_recorded: true`, and `receipt_readback` with `verified`, `owner_match`, `session_match`, `query_match`, `target_match`, and `snapshot_match` all true in that attempt row. These are user-supplied claims, not independently attested by this tool. Retain the actual confirmation event and protected receipt/readback trace for external review.

Each system has ES, PT, overall, and per-language `by_repeat` summaries. Rates are count/denominator; `unique_cases` is distinct from pooled attempt count across repeats. Safe inquiry and verified simulated intake are separate; neither means dispute resolution or refund. `correct_handoff` requires transfer **and** a complete packet; `missed_handoff` includes absent/incomplete required transfers. A saved packet does not prove human pickup. Cost per safe resolution uses all attempt costs divided by successful safe inquiry resolutions; it is undefined with zero successes and unknown if any attempt cost is unknown. p50/p95 use linear interpolation across all attempt latencies, including failures. Small samples and repeated case dependence must be disclosed.

The private round9 evaluation protocol and official organizer statement, PDF pp. 5–6, govern the actual comparison. The old 120-case router diagnostic is intent-only and cannot fill this input.
