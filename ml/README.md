# ML: measure before modelling

## 1. The dataset's labels are not learnable

Both diagnostics run on the published pipeline build and print aggregates only.

| Script | Question | Result on the real bucket |
|---|---|---|
| `python -m ml.inspect_texts` | Does transcript text predict `contact_reason`? | **No.** The best possible accuracy from text is 34.9%, identical to always predicting the majority class. The 171,321 transcripts are 2 base requests plus filler (42 distinct texts), and every text carries the global label mix (35/22/17/15/8/3%). |
| `python -m ml.inspect_fraud` | Does any behavioural feature predict `is_fraud`? | **No.** Every feature's AUC is inside the range produced by randomly permuted labels (e.g. amount 0.537 vs 0.533 random mean). The fraud rate is flat by month (~0.1%), and flagged customers follow the Poisson expectation for random labels. Only the pre-computed `fraud_score` correlates, and it is generated alongside the label. |

A model trained and scored on these labels would report ~99% on its test split (100% of test-split texts also appear in train) while learning nothing. So:

- **Fraud / security routing is a deterministic rule** in the assistant, not a model.
- **The learned component is an intent router trained on team-authored utterances**, evaluated on a separate held-out set.

## 2. Intent router

Given the customer's first message, it picks the flow: `inquiry` · `dispute` · `human` · `other`. [LABELING.md](LABELING.md) defines each class and the tie-breakers; for example, a security risk always goes to `human`.

```
python -m pip install -r requirements-ml.txt
python -m ml.router train                        # CV model selection on train, one pass on test, reports
python -m ml.router predict "me cobraron dos veces en oxxo"
```

| Piece | Choice | Why |
|---|---|---|
| Baseline | Ordered keyword rules, security first | What a team would ship without ML |
| Model | TF-IDF (char 2–5 within word boundaries + word 1–2) → logistic regression | Tolerates typos, missing accents, Mexican / Colombian / Argentine slang and Portuguese spelling; small, fast and inspectable |
| Abstention | Top probability below τ → hand off to a person | A wrong automation costs more than a handoff |
| Model selection | C and τ chosen by 5-fold CV on **train only** | The test set is touched once |
| Safety metric | `human` messages that were automated | Reported separately from accuracy |

**Data**

- `data/router_train.csv`: 307 phrases (≈80 per class, 15% Portuguese), written by Claude (AI) for the team and generated by `data/build_train.py`.
- `data/router_test.csv`: **held-out, team-authored**, written without seeing the training set. Not yet delivered.
- `data/router_test_provisional.csv`: 60 WhatsApp-style phrases written by the same author as train. Used only until `router_test.csv` exists, and every report says **PROVISIONAL**. A near-duplicate check (character cosine ≥ 0.8) runs on every evaluation, and 3 leaked phrases were replaced.

**Results**: [`docs/ml/router_report.md`](../docs/ml/router_report.md), with accuracy and 95% bootstrap CIs, per-class and per-language scores, the confusion matrix, the abstention trade-off curve, and every error.

Limitations: the training data is authored rather than collected from real customers, and a 60-phrase test gives wide confidence intervals. The model only sees the first message; the assistant still confirms the transaction before any dispute is opened.
